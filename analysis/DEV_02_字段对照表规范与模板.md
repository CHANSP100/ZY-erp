## 8. 字段增改约定（必守，2026-05-23 用户拍板）

当您或 AI **新增、修改**对照表字段时：

| 规则 | 说明 |
|------|------|
| **阶段** | 一律写入 **「本期」**，不得放入二期或附录末尾 |
| **位置** | 按 **截图/口述/栏位顺序** 插入到「本期字段」表的 **对应序位**，**禁止**仅追加在本期表格最后一行之后 |
| **状态** | 该菜单对照表文件头 **状态改为「待确认」**，直至您将文件头改为 **「已确认」** |
| **总表** | 同步更新 `菜单字段对照总表_待确认.md` 对应节，同样 **待确认** |
| **开发** | **待确认** 期间不得写该菜单业务页（DEV-01 门禁） |

### AI 执行步骤（增改字段时）

1. 在 `gen_field_mapping_docs.py` 的 `SCREEN_ORDER` 中 **插入**新字段到正确序位（不是列表末尾）。
2. 若为本期 UI 字段，同步写入 `DBJS_FIELDS`（或等价本期集合）。
3. 将该菜单登记到 `PENDING_CHANGE_MENUS`（生成器会自动输出 **待确认**）。
4. 重新生成 `analysis/字段对照/<菜单>.md`，**不要**手动把新行贴在文档最下面。
5. 等您确认后：从 `PENDING_CHANGE_MENUS` 移除，写入 `CONFIRMED_MENUS`，再生成一次。

### 状态取值

| 状态 | 含义 |
|------|------|
| 草稿 | 初稿，尚未请您审 |
| **待确认** | **有增改字段，请您审本期顺序与栏位** |
| 已确认 | **文件头状态 = 已确认**；整份对照表可开发 |

## 9. 单据类对照表章节顺序（必守，2026-05-23 用户拍板）

**单据**（表头+表身）分文件结构：

| 顺序 | 章节 | 内容 |
|------|------|------|
| 1 | **本期 — 表头** | 表头本期字段（按栏位顺序） |
| 2 | **本期 — 表身** | 表身本期字段（按栏位顺序） |
| 3 | **二期（置后）** | 表头二期 + 表身二期，均放在本期之后 |

**档案/单表** 仍为一表内：**本期 → 二期**。

生成器 `gen_field_mapping_docs.py` 已按此输出；手工改对照表时请遵守同一顺序。
