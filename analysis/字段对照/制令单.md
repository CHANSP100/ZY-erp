## SUNLIKE 扩展字段机制（FACE）

旧系统用三张表管理扩展字段；新系统 **读写 `MF_MO_Z` 与 FACE 兼容**，但 **本期界面不预置任何扩展列**，由用户像旧 ERP 一样自行添加。

| 表 | 作用 | 新系统 |
|----|------|--------|
| **FACE_FLD** | 字段定义（菜单、H/B、类型、落库表） | 用户「添加扩展字段」时写入；可同步读账套已有定义 |
| **FACE_EXP** | SQL 公式（联动/计算） | 对应扩展字段 `sql_expr`；令牌 **`:H.` / `:B.`** |
| **FACE_TBL** | 窗体布局二进制 | 二期（Web 不依赖） |

| FACE 字段 | 含义 |
|-----------|------|
| `MENU_NAME` | 菜单代号（账套 `MRPAC`） |
| `TABLE_SIGN` | `1`=表头（H），`2`=表身（B） |
| `TABLE_NAME` | 物理扩展表（制令单表头扩展为 `MF_MO_Z`） |

> 账套若已有 `FACE_FLD`（如 JYY、ren1 等），**数据仍读写 `MF_MO_Z`**；对照表不列入本期，避免与「用户自制扩展」冲突。

### 计算字段 / 纯显示字段（无物理列）

| 类型 | 是否落库 | 实现方式 | 谁配置 |
|------|----------|----------|--------|
| **主表原生字段** | 是（`MF_MO` / `TF_MO`） | 对照表「本期」+ 表单骨架写死 | 开发按对照表 |
| **扩展物理字段** | 是（`MF_MO_Z` 等 `_Z`） | 扩展字段 `field_source=input`，`persist=1`，自动 `ALTER TABLE` 加列 | **用户**在表单右键「添加扩展字段」 |
| **扩展 SQL 字段** | 否（或存盘时回写 Z 列，同 FACE_EXP） | 扩展字段 `field_source=sql` + `FACE_EXP`/Sunlike SQL；打开/存盘/审核前按表达式 **重算** | **用户**添加并维护 SQL |
| **列表 SQL 列** | 否 | 列表设计 `persist=0` + `sql_expr`，仅列表展示 | 管理员/用户 |

**结论：** 没有物理列、仅展示或计算的字段，**优先**走「扩展字段 → SQL 类型」（与旧系统 `FACE_EXP` 一致），由 **客户/实施自行添加**。
