# DEV-06 权限设置 — 方案说明

> **状态：已确认 · 验收通过**（2026-05-24）  
> **范围：仅 analysis 文档；不写 `erp-new` 业务页。**  
> **与登入关系：登入（认证）已单独实现并验收；权限（授权）为本菜单单独立项、单独验收。**

## 1. 用户拍板（本期范围）

| 项 | 您的选择 | 说明 |
|----|----------|------|
| 菜单权限 | **要** | 按 SUNLIKE `PSWD1` / `MENUNAME`：能否打开菜单 + 查询/新增/修改/删除/打印 |
| 用户维护 | **要** | 账号、名称、密码、部门、启用停用、管理员标记等（`PSWD`） |
| 数据权限 | **要** | 部门范围（`DEP` + `DEPRO_NO` / `DEPRO_SET`）；仓库范围（见 §4.3，库表待您确认） |
| 登入 | **已做、分开验收** | `/login` + Token；不并入本菜单开发 |

## 2. SUNLIKE 9.0 对标（库表依据）

来源：`analysis/all_columns.txt`、`旧ERP文件/逆向关键资料.md`、`旧ERP文件/ERP_Forms_List.md`（`TMENUFUNC` = 菜单与功能权限）。

| 逻辑对象 | 物理表 | 用途 |
|----------|--------|------|
| 用户主档 | **PSWD** | 账号、密码、部门、有效期、管理员、部门群组等 |
| 用户×菜单权限 | **PSWD1** | 每用户每 `PGM`（程序/菜单代号）一行：DSP/APD/UPD/DEL/PRT + 字段级 R_* |
| 菜单权限模板 | **MENUNAME** | 按 `PGM` 的默认权限名（DSP=查询、APD=新增…） |
| 角色 | **PSWD_RO** / **ROLE** / **PSWD1_RO** | 角色主档 + 角色菜单权限；`ROLE.MENUINFO_*` 为二进制菜单树 |
| 用户↔角色 | **PSWD_ROLE** / **ROLE_GR** | 多角色挂用户 |
| 部门群组 | **DEPRO_SET** | `DEPRO_NO` + 多行 `DEP` → 数据可见部门范围 |
| 旧菜单代号 | **FASEJ** | 密码管理（主表 PSWD） |

**旧 ERP 菜单对照：** `FASEJ` → 界面「密码管理」→ 表 `PSWD`（`analysis/menu_rem_all.txt`）。

**新系统菜单代号（建议）：** `SysAuth`（系统管理 · 权限设置），路由 `/sys/auth`；物理表仍对齐 **PSWD / PSWD1**，便于日后接 DB_11。

## 3. 与当前 `erp-new` 的差异

| 项 | 当前实现 | 目标（本方案） |
|----|----------|----------------|
| 用户表 | SQLite `sys_user`（`usr_id`,`name`,`pwd`,`is_admin`） | 迁移/映射为 **PSWD** 语义；`is_admin` ↔ `COMP_BOSS` |
| 登录 | `/api/auth/login`、Token | **保持**；登录页不改，只读权限结果 |
| 菜单 | `MainLayout.vue` 写死全部菜单 | 按 **PSWD1.DSP**（或管理员）过滤侧栏 |
| 接口 | `requireAdmin` 少数管理接口 | 按 **PGM + APD/UPD/DEL** 校验；管理员 bypass |
| 仓库数据 | 未过滤 | 列表/单据按 **用户仓库权限** 过滤（DEV-01 §1.2） |
| 部门数据 | 未过滤 | 按 **DEP / DEPRO_SET** 过滤（待确认规则强度） |

## 4. 功能结构（Web 一期 UI）

金蝶云星空视觉；业务 1:1 SUNLIKE。建议 **单页多页签**（非单据头身）：

```
系统管理 → 权限设置 (/sys/auth)
├── 页签1 用户列表（PSWD）          ← 本期
├── 页签2 菜单权限（PSWD1 矩阵）    ← 本期
├── 页签3 部门数据权限（DEPRO）     ← 本期
├── 页签4 仓库数据权限              ← 本期（存储见 §4.3）
└── 页签5 角色权限                  ← 二期（PSWD_RO / PSWD1_RO）
```

### 4.1 用户列表（本期）

- 列表：查询 `USR`、`NAME`、`DEP`；列含管理员、启用日期、停用日期。
- 弹窗：维护对照表「本期」字段；密码修改单独按钮（不改登录页）。
- **规则：** `COMP_BOSS=T` 视为系统管理员，拥有全部菜单且 bypass 数据权限（与现 `is_admin` 一致）。
- **停用：** `E_DAT` 早于今天或业务约定停用 → 禁止登录（登录接口校验，属登入联动，验收可分开测）。

### 4.2 菜单权限（本期）

- 左侧：用户树或用户下拉（仅管理员可进本页）。
- 右侧：树形 **本系统已上线菜单**（与 `MainLayout` / 路由一致），叶子对应 `PGM`。
- 格子：勾选 **查询(DSP)、新增(APD)、修改(UPD)、删除(DEL)、打印(PRT)**。
- **PGM 编码：** 与 SUNLIKE 菜单代码一致（如 `InvCA`、`FasECA`）；新系统新增 `SysAuth` 自身需一行且仅管理员可改。
- **侧栏：** 无 DSP 权限的菜单不显示；直链 URL 访问返回 403。
- **按钮：** 无 APD 隐藏「新增」；无 UPD 禁止存盘/改；无 DEL 禁止删；无 PRT 禁止导出/打印（与 DEV-01 单据状态按钮叠加关系见 §5.2）。

### 4.3 数据权限（本期）

**部门（SUNLIKE 原生）**

- 用户主档 **DEP**：所属部门。
- **DEPRO_NO** + **DEPRO_SET**：部门群组，多行 `DEP` 表示可查看/操作的部门集合。
- **过滤规则（建议默认，待您确认）：** 档案/单据列表 `DEP`（或表头部门字段）落在「本人 DEP ∪ DEPRO_SET 部门列表」内；管理员不过滤。

**仓库（DEV-01 要求；库表待确认）**

- 旧库 **未在 `all_columns.txt` 中发现** 独立的 `USR+WH` 权限表；可能存于 `PSWD.MOD` 二进制或其它模块。
- **Web 一期建议（待确认）：** 新增映射表 `sys_user_wh(usr_id, wh)`，界面多选 `MY_WH`；查询/单据带 `WH` 条件时自动 `IN (...)`。
- 若您坚持 **零新表**：需从 DB_11 导出仓库权限真实表名后再改对照表（标为阻塞项）。

### 4.4 角色（二期）

- `PSWD_RO`、`PSWD1_RO`、`ROLE`、`PSWD_ROLE` 整包二期；一期可用「复制权限到用户」简化运维。

## 5. 业务规则摘要

### 5.1 权限判断顺序

1. 未登录 → 401（登录页）。
2. `COMP_BOSS` / 管理员 → 通过（菜单全显、数据不过滤）。
3. 菜单 `PGM` 无 DSP → 403 / 侧栏隐藏。
4. 操作按钮 → 查 PSWD1 的 APD/UPD/DEL/PRT。
5. 列表/开窗数据 → 部门 + 仓库过滤。

### 5.2 与 DEV-01 单据状态按钮

| 能力 | 一期建议 |
|------|----------|
| 存盘、改单 | 需 **UPD** |
| 删单 | 需 **DEL** |
| 导出/打印 | 需 **PRT** |
| 审核、反审核、提交、作废 | **待确认**：`PSWD1` 无独立审核列；可选方案：① 并入 UPD；② 二期增加 `CHK`/`SUB` 列；③ 对标 `OKID`（`MENUNAME`） |

**默认建议（写入对照表备注）：** 一期 **审核/反审核/提交** 与 **UPD** 同权；您若需 SUNLIKE 细粒度拆权，二期再加列。

### 5.3 字段级权限（PSWD1 的 R_*）

| 字段 | 库注释（推断） | 阶段 |
|------|----------------|------|
| R_CST | 成本相关 | 二期 |
| R_QTY | 数量 | 二期 |
| R_AMT | 金额 | 二期 |
| R_TAX | 税额 | 二期 |
| R_MENU | 菜单 | 二期 |
| R_USR | 用户 | 二期 |
| R_OTH1 / R_OTH2 | 其它 | 二期 |
| R_GO | 执行/过账类 | 二期 |

## 6. 技术实现要点（供 DEV-03 阶段用，本期不写代码）

| 层 | 要点 |
|----|------|
| 库 | SQLite 原型：`pswd`、`pswd1`、`depro_set`、`sys_user_wh`；或扩展 `sys_user` 并增子表 |
| 登录 | 校验 `PSWD` 存在、密码、`E_DAT`；返回权限摘要（菜单列表 + admin + dep_wh） |
| 前端 | `useAuth` 增加 `permissions`；路由 `meta.pgm`；`beforeEach` 校验 DSP |
| 后端 | `requirePgm('InvCA','UPD')` 中间件；列表 API 自动加 `dep`/`wh` 条件 |
| 迁移 | 现有 `admin`/`user01` 种子写入 `pswd`/`pswd1` |

## 7. 验收标准（权限设置菜单，与登入分开）

**登入（已完成，可回归）：**

- [ ] 正确账号密码可进系统；错误密码提示一致
- [ ] 退出后不能访问业务 API

**权限设置（本菜单，对照表确认后开发）：**

- [ ] 管理员可增删改用户、改密码
- [ ] 非管理员不能进「权限设置」页
- [ ] 取消某菜单 DSP 后，侧栏不显示且 URL 403
- [ ] 取消 APD/UPD/DEL 后，对应按钮不可用或 API 403
- [ ] 部门/仓库过滤后，用户仅能看到授权范围内数据
- [ ] 与 SUNLIKE 字段名、中文标签一致（以对照表为准）

## 8. 拍板结论（2026-05-24 已确认）

| # | 问题 | 结论 |
|---|------|------|
| 1 | 菜单代号 | **SysAuth**（PGM 列仍用 InvCA 等 SUNLIKE 代码） |

| 5 | 角色 | 整包 **二期** |
